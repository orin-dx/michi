michi-core: what a response reports about itself now has one source each, so its text and JSON cannot contradict each other. A section's `truncated` is derived (its total is above its count), the budget's `sections[n]` roll-up is written from the response's own sections, and the budget's `truncated` is also true whenever a section was cut. The root keys michi writes itself are one reserved list for every writer, and it now includes the error document's keys, so a successful response can no longer render an `error:` / `message:` document from caller data. A provenance label `fingerprint` is always rejected, because it read exactly like the real fingerprint.

Breaking: `Section`'s fields are private; read them with `name()`, `body()`, `count()`, `total()` and `truncated()`. `Section::truncated(bool)` and `Section::returned_count(n)` are removed; a text section that stands for several items is `Section::text_with_count(name, body, n)`, and `SectionBody::Text` is now `Text { text, count }`. `SectionCost` and `BudgetSummary::section()` are removed, and the budget's JSON no longer has a `sections` array (the response's `sections` carries those counts). `truncated_section` now takes `(name, fields, &outcome, row, guidance)` and builds the rows from `outcome.kept()`. `budget`, `sections`, `provenance`, `error`, `message`, `causes` and `exit_code` join `totalCount`, `help`, `recovery` and `truncated` as reserved (`truncated` was already a reserved type name and is now a reserved KV key too): as a type name (`render_toon`, `list`), a KV key (`render_kv`, `kv_items`) or a section name they are a validation error, and the error messages list the reserved keys.

Migration: `.truncated_section(Section::toon(name, f, rows), &outcome, g)` becomes `.truncated_section(name, f, &outcome, |item| row_of(item), g)`. Drop `.truncated(..)` on sections and `.section(SectionCost::new(..))` on budgets. Rename any KV key or list named after a reserved key (for example a `message` field becomes `commit_message`). In JavaScript, `renderKv`, `renderToon` and `kvItems` reject the same reserved names.
