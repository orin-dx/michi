# michi-pipeline

## 0.3.1

- Released together with the `michi` fixed group.
- Joined the `michi` group at this version.

## 0.3.0

- **Breaking:** the execution API is redesigned (see `docs/spec/08-pipeline-execution.md`). `execute_pipeline`, `execute_pipeline_parallel`, `StepDependencies`, positional runner lists, `CircuitBreaker::call`/`CircuitBreaker::new(retry, timeout, threshold, open)` and the `StepCountMismatch`, `UnknownStepId`, `DuplicateStepId` and `CyclicDependency` error variants are removed. In their place:
  - `StepId` and `RunId` are validated slugs (1 to 64 ASCII letters, digits, `_`, `-`, `.`). `RunId::unique(prefix)` builds one without a UUID dependency.
  - `ExecStep` defines a step (id, display name, `depends_on`, runner, optional retry, attempt timeout, deadline and breaker key). `Plan::new` validates every step up front and returns all violations at once as `PlanError` (duplicate ids, unknown and self dependencies, cycles). `Plan::execution_order()` is the dry run; `Plan::fingerprint()` hashes ids and dependencies.
  - `execute(&plan, run_id, &opts)` returns a `#[must_use]` `RunRecord` instead of mutating a `Pipeline`: per-step status, reason, error, attempts with their replay class, timing and root cause; `outcome()` is `Succeeded` only if every step completed; `root_causes()`, `consequential()`, `needs_verification()`, `completion_order()`, `error()`, `to_pipeline()` and `render()`.
  - `resume(&record, &plan, &ResumeOptions)` continues a run under the same run id: completed steps become `CompletedEarlier` and are not re-run, a changed plan is refused (`ResumeError`), and steps whose outcome is unknown are re-run only if idempotent or verified by the caller (`Verification::Applied` / `NotApplied`).
  - `ExecOptions`: `Mode::Sequential` (default) or `Mode::Parallel { max_concurrency }`, `FailurePolicy::SkipDependents` (default) or `FailFast`, retry policy, per-attempt timeout (default 30 s), per-step deadline, jitter seed, cancellation token and grace period (default 5 s), retry budget, breaker registry and observer.
- **Breaking:** `Step::run` takes a `&StepContext` (run id, step id, attempt, child cancellation token, deadline, `idempotency_key()` = `run_id:step_id`) instead of the attempt number, and `Step::is_idempotent() -> bool` is replaced by `Step::replay() -> Replay` (`NotIdempotent` by default, or `Idempotent`). `step_fn` closures receive an owned `StepContext`.
- **Breaking:** with the default `SkipDependents` policy, a failure skips only the failed step's transitive dependents; independent steps keep running, also in sequential mode. Before, sequential execution stopped at the first failure. `FailurePolicy::FailFast` restores stop-on-failure.
- **Breaking:** a non-idempotent step whose last attempt timed out, got HTTP 502/504 or was dropped after cancellation ends `OutcomeUnknown` and is never replayed automatically, by retry or by resume. A step dropped mid-flight is no longer reported as skipped.
- **Breaking:** cancellation now drops a running attempt once the grace period has passed, recording it as ambiguous; before, an in-flight step always ran to completion. Backoff sleeps end as soon as the run is cancelled.
- **Breaking:** a panicking step ends `Panicked` and the run continues; before, `execute_pipeline_parallel` resumed the panic in the caller.
- **Breaking:** `CancellationToken` wraps tokio-util's token: it is awaitable (`cancelled()`) and has `child_token()`. New dependency: `tokio-util` 0.7 (not exposed in the public API).
- Circuit breakers are keyed: a `BreakerRegistry` holds one breaker per key (the step's `breaker_key`, defaulting to its id), shareable across runs. Each keeps the mutex-and-generation state machine; a step is admitted once and reports one outcome, a half-open probe gets one attempt, an open breaker ends the step `NotRun(CircuitOpen)` without invoking it, and cancellation is not counted as a failure.
- Retries are limited per run by `michi_core::resilience::RetryBudget` (10% of successes, reserve 10, cap 100 by default; `ExecOptions::no_retry_budget()` turns it off) and by an optional total step deadline.
- New `StepObserver` (or any `Fn(&RunId, &StepRecord)`): called synchronously as steps start and finish, so callers can persist progress; `StepRecord::in_flight` and `RunRecord::from_parts` rebuild a run after a crash, and resume treats a step left `Running` as possibly applied.
- A panic in a `StepObserver` is caught: the run continues, the observer still gets later events, and the new `RunRecord::observer_panics()` counts the caught panics (a record serialized without the field reads as 0), instead of the panic unwinding `execute`/`resume`, losing the record and dropping every running step.
- New `serde` feature: `RunRecord`, `StepRecord`, `ExecutionError`, the ids and the fingerprint serialize.
- New `ExecutionError::Interrupted` (attempt dropped after cancellation; ambiguous) and `ExecutionError::Panicked`. `ExecutionError` is now `Clone` and `PartialEq`, and `ExecutionError::replay_class()` and `ReplayClass` are public.
- New divan bench `scheduler`: plan validation and sequential and parallel execution of 500 no-op steps.
- One replay rule decides both whether `CircuitBreaker::call` re-invokes a step and whether the returned error says replay is safe. A timeout (the breaker's own, or one the step returns, also when wrapped in `StepFailed`) and HTTP 502 or 504 are ambiguous: the attempt may have committed. The breaker re-invokes the step after one only if the step opts in with the new `Step::is_idempotent()` (default `false`), or `FnStep::idempotent()` for closures. HTTP 429 and 503 mean "not processed" and are still retried for every step, so a step that may have committed must not report them. Circuit-open and cancellation never ran the step. Other errors are unchanged.
- **Breaking:** for a non-idempotent step, an ambiguous outcome now comes back as the new `ExecutionError::AmbiguousOutcome { source }` instead of a bare `Timeout` or `Http { status: 502 | 504 }`. That includes the `source` of the `StepFailed` that `execute_pipeline` and `execute_pipeline_parallel` return. `is_retryable()` is `false` for it. Its `DomainError` keeps the inner code, is not retryable, has no `retry_after`, and carries a hint telling the agent to verify whether the operation completed. An idempotent step's ambiguous outcome is still returned bare and stays retryable.
- The `StepFailed` to `DomainError` conversion now keeps the inner error's hints and recovery hint. Before, it rebuilt the error and dropped them.
- **Breaking:** `execute_pipeline` rejects duplicate step ids with `DuplicateStepId` before running anything, the same as `execute_pipeline_parallel`. Before, it ran them.
- **Breaking:** `execute_pipeline` resets every step to `Pending` at the start of a run. When a step fails, every later step is now marked `Skipped` instead of being left alone. Before, statuses from an earlier run survived: re-running a pipeline that started `[Completed, Completed]` with a failing first step left `[Failed, Completed]`, and the second step never ran.
- `execute_pipeline_parallel` rejects duplicate step ids with `DuplicateStepId` before running anything, including ids no edge mentions.
- Cycle detection is iterative, so very large graphs (100,000 steps) no longer overflow the stack.
- `CircuitBreaker` keeps phase, probe and failure count in one state machine. An outcome from a call admitted before the breaker last changed state is ignored: it can no longer reopen a recovered breaker, extend the open window or reset the failure count.
- Depends on `michi-core` (exact version) instead of `michi-core` and `michi-resilience`; versions in lockstep with it.
